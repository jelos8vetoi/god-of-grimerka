# Controlled Balance Lab

Данные этого режима описывают управляемые испытания, а не пользовательские забеги. Он использует боевые скрипты игры и журнал фактических попаданий, отдельно от сохранений кампании и `user://survival_reports/`.

## Запуск

Из папки `godot/`, PowerShell:

```powershell
$godot = '../tools/godot/Godot_v4.7.2-stable_win64_console.exe'
& $godot --headless --disable-render-loop --fixed-fps 60 --path . -- "--balance-lab-check=$env:TEMP/grimerka-balance"
```

Используйте `--fixed-fps 60` для воспроизводимого шага. Полный прогон ограничен пятью минутами реального времени, каждый замер — своим числом физических тиков. Можно проверить только один сценарий через `--balance-lab-scenario=single`. Выбирайте отдельные папки для разных сборок.

Для нового замера с базовым отчётом передайте `--balance-lab-baseline=<путь к balance_lab.json>`. Для сравнения двух готовых отчётов используйте:

```powershell
& $godot --headless --path . -- "--balance-lab-check=$env:TEMP/grimerka-comparison" "--balance-lab-baseline=C:/reports/previous/balance_lab.json" "--balance-lab-current=C:/reports/current/balance_lab.json"
```

## Условия

### Панель разработчика

Запустите игру с аргументом пользователя `-- --balance-lab`. Для Godot из исходников добавьте `--path .` перед разделителем. Обычный запуск открывает главное меню игры.

Панель позволяет выбрать один из последних 50 отчётов Survival, открыть два JSON контролируемых испытаний и просмотреть девять разделов. Кнопка «Испытать» запускает отдельный экземпляр той же игры в headless-режиме. После его завершения новый отчёт открывается в панели. Выберите базовый JSON, чтобы получить дельты. Оба пути и множители показаны в разделе сравнения.

Три множителя стенда (0,5–2,0, исходное значение 1) управляют множителем урона героя, начальным HP мишени и интервалом обычных атак противника. Командные удары с собственными формулами сохраняют свои правила. Интервал проверяйте в `boss` или `endurance`, где мишени могут атаковать. Тот же профиль можно передать через `--balance-profile=<JSON>` вместе с обычным CLI стенда. Формат: `{"damage":1.2,"hp":1,"cooldown":1}`.

Эксперименты, их профиль, JSON/CSV и экспортированные предложения находятся в `user://balance_lab/`. Предложение содержит выставленный профиль, последний измеренный профиль, пути к отчётам и гипотезы с основаниями и заданиями на перепроверку. Коэффициенты кампании меняет разработчик отдельной правкой.

Пороговые сигналы служат для отбора эпизодов. Например, изменение измеренного урона комбо примерно на 20%, серия из пяти применений без попаданий, короткий бой с боссом или превышение ранга карточки заслуживают проверки контекста. Раздел о финальных ударах сопоставляет поражения с одинаковыми улучшениями, множителем HP и отпечатком баланса. Игровой опыт пользователя неизвестен. Для проверки гипотезы нужны дополнительные seed, повторы и отдельные игровые наблюдения.

- `single`, `shield`, `group3`, `group5` — одно и то же расположение по дуге. Мишени закреплены, повышенный запас HP предотвращает раннее завершение теста. У MOD работает фронтальный щит.
- `boss`, `endurance` — живой LIL DREY либо три обычных противника, нормальное здоровье, движение, атаки и правила входящего урона. Стенд использует фиксированный сценарий ввода, без иммунитета.
- `tag`, `duo`, `overdrive` — пара Пахан с VOZDUH и madk1d со скейтом. В Tag смена вызывается после первого попадания Пахана и должна породить командный удар. В Overdrive стартовый командный ресурс заполнен, цель — LIL DREY с обычным HP и реальным лимитом урона команды.
- Для каждой комбинации используются два seed. Все прогоны стартуют с чистых героев, без сюжетной прокачки и карточек Survival. Настройки, позиции, состав, начальные ресурсы и фактически запущенные атаки входят в JSON.

## Повторяемость (проверено 2026-11-20)

Два полных прогона одной сборки с одними зёрнами: 70 из 78 замеров совпали до последней цифры — все сценарии с
закреплёнными мишенями (`single`, `shield`, `group3`, `group5`, `tag`, `duo`, `overdrive`). Восемь замеров «живых»
сценариев (`boss`, `endurance`) разошлись: урон до 12 %, полученный урон на 3–10 HP. Зерно задаёт случайные числа, но
не весь ход живого боя. Разницу в `boss` и `endurance` меньше примерно 15 % считайте шумом и перепроверяйте повтором.

## Интерпретация

`balance_lab.json` содержит отдельные измерения, журнал агрегатов атак и сводку. CSV содержит сводку по каждой метрике. DPS считается за всё измерительное окно, включая паузу до последней границы. Урон комбо доступен для подтверждённой связки в `single`, с учётом её попаданий и долетевших в отведённом окне снарядов. Время считается до окончания связки, в тиках стенда. Незавершённый шаблон остаётся без метрики комбо. ТЯГА-812 использует последовательность действий собственного контроллера.

`bottles_spent` — фактически списанные бутылки. Для тепла, ритма, потока и зарядов фиксируются начальный, конечный и пиковый уровни, для Hype — чистый расход. `stagger_requested` отражает запрошенную силу контроля до сопротивления, без подмены её временем оглушения. Выживаемость измеряется полученным уроном, выбываниями и остатком здоровья команды.

Сравнение показывает среднее, диапазон, выборочное стандартное отклонение, размер выборки, абсолютную и процентную разницу. Процент при нулевой базе отсутствует. При разных исходных условиях дельта не выводится. Подсказки о возможных причинах — направления для проверки, а два коротких замера не подтверждают статистически значимый дисбаланс. Первый отчёт становится базовым для следующих сборок.
