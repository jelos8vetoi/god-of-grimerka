# GOD OF GRIMERKA — памятка для Claude

Экшен от третьего лица про русский SoundCloud-рэп: Пахан с Балоном VOZDUH и его кент madk1d идут через девять серверов Облака. Репозиторий: `jelos8vetoi/god-of-grimerka`, работают двое (владелец и Shur, `rofaan`) — **ветка на задачу и Pull Request в `main`**, подробности ниже в разделе «Совместная работа».

**Сейчас в игре одна глава** (`Menu.CHAPTERS = 1`, `game.chapters()`): после босса первой главы — экран «Глава 1 пройдена». Главы 2–9 (сюжет в `story.json`, локации, боссы) не удалены, но не запускаются; владелец планирует вместо них открытый мир. Проверки `--smoke`, `--autotest`, `--chapter=N` по-прежнему ходят по всем главам.

## Две версии игры

| Версия | Где | Статус |
|---|---|---|
| **Godot 4.7** | `godot/` | основная, сюда идёт вся новая работа |
| Браузерная (three.js) | `index.html`, `js/`, `models/`, `tools/installer/` | старая, полная; источник сюжета и баланса. Не развивать без просьбы |

## Как проверять (обязательно после правок)

**Быстрый путь — `node tools/checks.cjs`** (по умолчанию все проверки; группы: `combat`, `modes`, `race`, `ml`, `fn`,
`ui`, `real`; или по именам — `node tools/checks.cjs --list`). Проверки идут **параллельно** (`--jobs=6`) и в
**ускоренном времени**: `--fixed-fps 60 --disable-vsync` + ключ `--clock=60` — игровое время отвязано от настоящего,
ожидания в проверках идут по игровым часам `GameClock.ms()` (`game_clock.gd`; в обычной игре это те же
`Time.get_ticks_msec()`). У каждой проверки своя папка данных (`APPDATA` → `%TEMP%/grimerka-checks/appdata/<имя>`):
сохранения игрока не трогаются, проверки друг другу не мешают. Итог — таблица, логи и снимки в
`%TEMP%/grimerka-checks/run-<время>/`, код выхода 1 при любой ошибке. В настоящем времени остаются звук, сеть и iPod;
`--real` — всё по-старому (по одной, настоящее время). **В новых проверках ждать по `GameClock.ms()`, а не по
`Time.get_ticks_msec()`** (настоящие часы — только для замеров кадра и для сети), и в игровом коде то же для
перезарядок и защиты от двойного нажатия — иначе в ускоренной проверке они «проспят» события. Ручные команды ниже
по-прежнему работают.

- Проверки идут **тихо** и не мешают человеку за компьютером: любой ключ запуска (кроме `--launcher`) включает `MouseMode.make_quiet` (`mouse_mode.gd`) — окно без фокуса в правом нижнем углу, курсор не захватывается. Захват мыши в коде — только через `MouseMode.set_to(...)`, а не `Input.mouse_mode = …` (проверки сверяют `MouseMode.want`).
- Godot завершается с кодом 0 даже при `SCRIPT ERROR` — **читать вывод**, искать `SCRIPT ERROR` и `ERROR:`.
- После правок боя или стилей запускать **все** проверки систем (`--flowcheck`, `--tagcheck`, `--execcheck`, `--hypecheck`, `--basecheck`, `--bottlecheck`, `--tyagacheck`, `--madkcheck`, `--duocheck`, `--hudcheck`), а не только проверку своего этапа: они держатся на графах стилей и ломаются от чужих правок. Ручные проверки без `--fixed-fps` не запускать одновременно с `--combatcheck` — плывут тайминги (через `tools/checks.cjs` можно: там у всех своё игровое время).
- Скриншоты и листы поз смотреть глазами: «скрипт без ошибок» не значит «выглядит правильно».
- Папки для скриншотов — вне репозитория (временная папка сессии).

## Совместная работа и сборка на GitHub

Работают двое, у каждого свой ИИ-помощник. Общие правила — в `AGENTS.md` и `COLLABORATION.md`, они обязательны и для Claude:

1. Перед задачей: `git fetch --prune origin`, `git switch main`, `git pull --ff-only`, затем ветка задачи `feature/…`, `fix/…` или `chore/…`.
2. **В `main` напрямую не коммитить.** Коммит в ветке → `git push -u origin HEAD` → `gh pr create --base main --fill` → влить Pull Request.
3. Никаких `push --force` и `reset --hard`. Не трогать файлы, которые сейчас меняет другой автор.
4. Перед PR дописать сверху в `godot/CHANGELOG.md` раздел `## дата · что сделано` — пункты простыми словами, что изменилось для игрока.

Сборку руками не выкладываем: после вливания PR в `main` GitHub сам собирает .exe и обновляет релиз **`godot-build`** (`.github/workflows/godot-build.yml`, шаг — `node tools/publish-godot.cjs`). Ссылка на игру всегда одна:
https://github.com/jelos8vetoi/god-of-grimerka/releases/tag/godot-build

Лаунчер (`tools/launcher/Launcher.cs`, `build.cmd`, ассет `GOD-OF-GRIMERKA-Launcher.exe` в том же релизе): скачивается один раз, ставит игру в `%LOCALAPPDATA%GOD OF GRIMERKA Godot` (папка `GOD OF GRIMERKA` занята старым лаунчером браузерной версии), сверяет SHA-256 файла в релизе с `installed.txt`, докачивает, сам обновляется и запускает игру с `-- --launcher=<путь>`. Ключи для проверки: `--check-only` (всё, кроме запуска игры), `--no-self-update`. Скачивание у лаунчера и установщика общее — `tools/launcher/FastDownload.cs` (8 частей по HTTP Range сразу с CDN, докачка оборванной части, без Range — одним потоком); оба `build.cmd` его компилируют.

Текстуры 3D-моделей импортируются со сжатием VRAM (`compress/mode=2`) и пределом размера (`process/size_limit`: трассы `assets/racing` — 1024, модели `assets/models` — 2048); без сжатия (`mode=0`) сборка раздувалась почти вдвое. Новые `.glb` — с теми же настройками в `.import` их текстур.

Установщик (`tools/setup/Setup.cs`, `build.cmd`, ассет `GOD-OF-GRIMERKA-Setup.exe`): рисованное окно в стиле меню (C#, GDI+), героев берёт из `tools/setup/heroes.png` — рендера моделей из меню (`Godot … -- --menu-render=<путь>`). Качает игру и лаунчер из релиза с проверкой SHA-256, ставит по умолчанию в `%LOCALAPPDATA%\\Programs\\GOD OF GRIMERKA`, кладёт метку `grimerka-install.txt` (по ней лаунчер держит игру в своей папке), `Uninstall.exe` и запись в HKCU. Данные игрока (`%APPDATA%\\Godot\\app_userdata\\GOD OF GRIMERKA`) не трогает без галочки. Подробно и ключи проверки — `docs/INSTALLER.md`. Старый `tools/installer` — от браузерной версии.

Игра сама проверяет обновление: в меню появляется кнопка «Вышло обновление», если коммит сборки (`godot/data/build.json`, пишется при сборке) не совпадает с коммитом в описании релиза.

Локально `node tools/publish-godot.cjs` нужен только для проверки (`--dry`) или если автосборка сломалась; он отказывается работать при незакоммиченных или незапушенных правках в `godot/`.

## Боевая система

- Аудит боевых анимаций и план по стилям Пахана (что есть, чего нет, порядок этапов, вопросы владельцу) — `docs/COMBAT_ANIMATION_AUDIT.md`; числа в нём — из `animaudit.gd`. Этапы 0–3 сделаны (разделы 8–11); решения владельца по рикошету, костям шланга и второй бутылке — в разделе 7.
- Аудит текущего боя, архитектура шести стилей, добиваний, Tag Team, прокачки и порядок этапов — `docs/COMBAT_SYSTEM_ROADMAP.md`. Новые боевые этапы сверять с ним; новых локаций, открытого мира и глав не делать.
- Баланс урона — `godot/docs/DAMAGE_BALANCE.md` (формула, все источники урона, таблицы «до / после»); коэффициенты — только в `balance.gd` (`Balance`: `STYLE_DMG` / `HEAVY_DMG` применяются к AttackData при сборке стиля в `Styles.by_id`, `MOMENT_CAP` — потолок суммы усилений момента в `player.damage_bonus` (Perfect Swap, Tag, ресурс стиля складываются), `RAGE_MUL`, `BOSS_HP`, `MOB_HP`, `DUO_OPEN` / `DUO_END`); после правки урона — `--damagecheck` (запись попаданий — `game.dmg_log`, только в проверке).
- Ядро боя и данные стилей — `docs/COMBAT_CORE.md`. В стиле тяжёлые после лёгких (`kind: "finisher"`) — завершители цепочки (Yakuza), а не добивания; добивания — отдельная система (раздел 4.6 плана).

## Меню и прокачка

- Навигация единая: главное меню — `menu.gd`, пауза — `pausemenu.gd`. Новые экраны встраиваются в них, вторые меню не создаются (`docs/UI_MENU_ARCHITECTURE.md`).
- **Вся будущая прокачка — только через вкладку «РАЗВИТИЕ» паузы** (`docs/PROGRESSION_MENU_INTEGRATION.md`); покупка — `game.buy_upgrade(k)`, не `_open_shop()`.
- Режим наушников (пока iPod играет в EarPods: музыка локации уходит в тишину — `HP_SILENCE_DB`, эффекты и окружение только тише — `HP_MUFFLE_DB`, в ноль их не глушить) живёт только в `audio.gd`; другие скрипты шины не глушат. Проверки не пишут настройки игрока: `main.user_play()` (iPod `persistence_enabled`).
- Настройки — одна система `settings.gd` (`Opts`, `user://grimerka_display.json`): строки `Opts.rows()` показывают и главное меню, и пауза; новые настройки добавлять туда и только работающие.
- Проверка: `-- --ipodcheck=<папка> --pause`; сквозная по всему интерфейсу — `--resolution 1280x720 -- --uiqa=<папка>` (снимки всех экранов, клавиши и мышь, настройки, 30 циклов паузы, FPS и узлы).

## Правила проекта

- Язык игры и общения — русский. Имена: Пахан, madk1d, Балон VOZDUH. Слова «back2u», «Ванёк», «бита» в текстах игры не использовать.
- GDScript: при `:=` от нетипизированного значения (словарь, лямбда, `game.*`) указывать тип явно — иначе «Cannot infer the type».
- В git не класть: `tools/godot/`, `dist/`, `godot/.godot/`. Модели и звук — можно (на треки у владельца права есть).
- Коммиты на русском, по делу; не переписывать историю; в `main` — только через Pull Request.
- Не менять версию движка и не переводить проект на `.tscn`-сцены без просьбы.

## Навыки (.claude/skills) — когда какой применять

Навыки установлены локально в этом проекте. Claude подхватывает их сам по описанию задачи; таблица ниже — чтобы выбирать точнее и не грузить лишнее.

| Задача | Навыки |
|---|---|
| Любая правка геймплея в Godot (общий порядок работы и проверки) | `godot-gamedev` |
| Ошибки GDScript, типы, await | `godot-gdscript` |
| Узлы, создание и удаление объектов, «freed instance» | `godot-nodes-scenes`, `godot-signals-groups` |
| Анимации, переходы, Tween | `godot-animation` (+ `game-feel` для сочности ударов) |
| Бой: хит-стоп, тряска, отдача, ощущение удара | `game-feel`, `rpg` (числа урона и прокачки) |
| Враги и боссы: поведение, фазы, выбор атак | `game-ai`, `ai-behavior-trees-utility-ai` |
| Столкновения, слои, лучи, зоны удара | `godot-physics` |
| Камера: слежение, наезд, стены | `camera-systems` |
| Свет, туман, материалы, «пересвечено/темно» | `godot-3d-essentials`, `godot-shaders` |
| Интерфейс: HUD, меню, диалоговое окно | `godot-ui-control` + `game-ui-ux` |
| Диалоги и сюжетные сцены | `dialogue-systems` |
| Управление, переназначение клавиш, геймпад | `input-systems` |
| Сохранение и «Продолжить» | `save-systems` |
| Звук и музыка | `godot-audio` |
| Низкий FPS, рывки, первый показ эффекта | `performance-optimization` |
| Данные врагов и оружия как ресурсы | `godot-resources` |
| Сборка .exe | `godot-export` |
| Автопроверки без окна, CI | `godot-gdscript-headless-testing` |
| Дизайн: механики, темп, баланс, документ | `game-designer` |
| Неясный API или флаг Godot 4.7 | `godot-docs-reference` |
| Нужен рабочий пример из официальных демо | `godot-demo-reference` |
